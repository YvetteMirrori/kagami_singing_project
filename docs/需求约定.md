# 本项目的需求约定

来源：本聊天中用户的歌词分析规范，以及 2026-10-19 的网页实现要求。后续开发以此为基础，避免依赖跨聊天记忆。

1. 用户在网页输入一段、多句日语原歌词，可能夹有从音乐软件复制的罗马音。罗马音可能有误，需要模型校正。
2. 使用 OpenAI 或兼容 OpenAI 的大模型分析，不使用旧版词典分词加普通翻译代理的实现。
3. 按原有顺序逐句分析，不跳句、不合并句子。副歌和重复句独立完整呈现，不得用“同上”“略”代替。
4. 每句固定四层：罗马音 → 原词分词 → 逐词翻译 → 整句翻译。原词大字体，其余较小。词的前三项在网页同一格中上下对齐；文本导出以 `|` 分隔，逐词翻译一一对应。
5. 汉字用括号标常用的正确平假名读音；特殊演唱读音采用实际读音。保留外来语、英语、德语原文。促音 `っ` 用 `~` 表示，长音与拨音按实际发音。
6. 逐词翻译严格按原文词序，不合并词义、不意译、不加解释。助词、助动词分别翻译或标简短语法功能。整句中文翻译自然流畅，允许调整语序。
7. 括号台词、独白、拟声词、语气词均保留并分析。简洁模式不增加注释、鉴赏或无关内容。
8. 网页需要真实模型接口，同时在未配置密钥时可用完整示例检查排版。示例与真实分析要明确区分。
9. 当前先完成本机可运行网页，后续可能供更多用户使用。密钥留在后端或当前页面会话，不持久化在浏览器。
10. 用户已明确要求删除旧网页和旧代理、从零重写，不能复用旧代码。保留原始参照文档。
11. 所有项目、说明、测试和截图均放在 `D:\0_桌面\Codex\日语小白唱见拯救计划` 文件夹中。
