# 日语小白唱见拯救计划

面向日语初学者与唱见的歌词分析网页。从零实现，全部文件都在此目录内。原始参照文档保留，不使用旧网页或旧翻译代理。

## 启动

需要 Node.js 22 或更新版本，无第三方运行依赖，也无需 npm install。

双击 **启动网页.cmd**，保持窗口开启，在浏览器访问 <http://127.0.0.1:8787>。

也可以在此文件夹打开 PowerShell：

```powershell
node --env-file-if-exists=.env server.mjs
```

首次打开会展示本对话提供的全部 33 句示例，重复句单独保留。示例是预先整理的数据，不会调用外部模型。后续打开恢复本机浏览器的草稿与结果。

## 真实模型分析

点击「开始逐句分析」时，如果本机还没有密钥，网页会弹出「模型设置」。填写 API 根地址、模型 ID、API Key 即可。支持 DeepSeek、OpenAI Chat Completions 及其他兼容服务；根地址不包含 `/chat/completions`，请以服务商文档为准。

- DeepSeek：根地址 `https://api.deepseek.com`，模型填写 `deepseek-flash`，输出模式选择「JSON 对象」。网页保存上次的连接设置，也可随时切换到 OpenAI。
- OpenAI：根地址 `https://api.openai.com/v1`，选择服务账户实际可用的模型，输出模式可选择「严格结构化 JSON」。
- 其他兼容服务：填写其 API 根地址与模型 ID；不支持 JSON Schema 时，选择「JSON 对象」；若也不支持该模式，可选择「仅提示词约束」。
- API 地址、模型名称、输出格式和密钥保存在本机浏览器；歌词草稿与分析结果也会自动恢复。可在模型设置中清除已保存密钥。
- 要长期使用服务器配置，复制 `.env.example` 为 `.env`，填写 `OPENAI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_MODEL`，重新启动。`.env` 已加入忽略文件。不要把实际密钥写进前端文件。
- 配置后，点击「开始逐句分析」。输入不会自动触发付费调用。模型结果有误时可导出 JSON 修订再导入。

当前没有实际密钥，开发验证使用模拟上游验证完整请求流程；真实模型的读音、翻译准确率、访问权限和费用需在配置自己的服务后确认。

## 分析与对齐

原词、罗马音和逐词译义来自同一个 `tokens` 数组；同一 token 的三项共用一个格子宽度，整句译文位于下方。使用前端格子布局，不依赖用空格凑齐。手机上的长句可以横向滚动。

- 每句按原顺序独立编号，不折叠重复句。
- API 使用紧凑线格式：模型只返回标音、罗马音、逐词义和整句翻译，服务端补回原句及字段名；33 句完整示例的 JSON 输出体积由 14,494 字符降至 7,055 字符（减少约 51%，字符体积为近似指标，实际 token/费用以服务商统计为准）。相同歌词和参考音的重复句只生成一次，结果再逐句展开；相同歌曲、服务和模型在服务进程缓存 24 小时，最多 1,000 句 / 10 MB。浏览器保存完全相同的最终分析，重复点击可直接显示且不请求模型。缓存以 API 密钥哈希隔离，不储存密钥。
- DeepSeek 官方 API 默认请求关闭思考模式，并按歌词长度估算输出上限（每句至少 120 token，总计限制为 1,200–12,000），避免推理 token 和过大生成上限；兼容服务和 OpenAI 请求保持其原有参数行为。页面会显示服务商返回的输入、输出 token 合计和可用用量；若服务商未报告则明确提示。
- 结构不合格时只重试尚未通过校验的句子，不再把已生成的大段错误回复再次发送。
- 汉字使用括号标平假名；特殊读音依赖用户提供的标音和罗马音参考。文字分析不能确认音源演唱读法。
- 促音使用 `~`，例如 `ko~cchi`、`i~ppo`。助词和助动词分别列出，逐词翻译不调整语序。
- 输入格式可选自动、只有原歌词、原文与罗马音成对。自动模式仅识别分音节罗马音，连续罗马音请选择成对模式；混有英文歌词时可选择原歌词模式，以完全避免误判。
- 40 句以内使用一次模型请求；更长的输入分批并发分析并按原顺序合并，流式更新生成状态。后端核验句子数、编号、原文和分词拼接；格式错误自动请求修复一次。该校验可发现遗漏或改写，无法证明语义或读音完全正确。
- 失败或取消保留之前的完整结果，不以半份结果覆盖。
- 可切换格子 / 简洁视图、调字号、专注阅读、复制四行文本、导入导出 JSON、导出 TXT、浏览器打印 PDF。全部重复句参与导出。

## 中文空耳（1.1.0）

点击阅读工具栏的「空耳」可一键显示或隐藏，默认关闭，刷新后保留选择。空耳位于罗马音下方、原词上方，与原来的每个分词格共用宽度；字号随原词调整，介于罗马音和原词之间。打印也遵循当前开关状态。

转换完全在浏览器内完成，不调用模型、不新增 token 或费用，已有分析和导入 JSON 可直接显示。复制和 TXT 保持原约定的四行结构。

规则来自项目内的 `五十音转空耳对照表.xlsx`，没有自行补充中文读音。`ki`、`ke`、`hi`、表内的 `gi` 及无中文对应的拗音保持罗马音；不认识的拼写、外语歌词和促音标记也保留。比如 `watashi` → `哇它西`，`kya` → `kya`。

更新 Excel 后，运行以下命令重新生成静态规则（Python 仅用标准库），再运行测试：

```powershell
python scripts/build-soramimi.py
node --test
```

`public/soramimi-data.mjs` 记录映射及源文件 SHA-256，`public/soramimi.mjs` 负责本地转换。版本变化见 `CHANGELOG.md`。

## 后续多人使用

当前为本机可运行版本，默认只监听 `127.0.0.1`，尚未发布公网。后端已实现输入上限（16,000 字符 / 200 句）、全局最多 2 个分析任务、每 IP 十分钟 20 次请求的基础限制。所有额度与计数为单进程内存，不作为公开服务的计费系统。

公开部署应由服务器环境变量统一配置模型；`HOST` 非本机地址时会忽略浏览器传来的模型凭证和服务地址。还需为公开服务接上 HTTPS、登录认证、用户配额、持久化限流及费用预算，反向代理需关闭 `/api/analyze` 的响应缓冲并允许较长响应时间。歌词涉及的版权与隐私规则应在公开运营前明确。
